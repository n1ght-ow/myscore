# MyScore 安卓个人版

一个面向 Redmi K80 Pro 与 Xiaomi Pad 6S Pro 12.4 的原生 Android 比分与赛程应用。手机保持单列赛程册，平板使用独立比赛工作台：宽屏三栏，窄窗口保留完整赛程并点击进入详情。中文界面，北京时间，无广告，无登录，不依赖 Google 服务，不使用厂商推送 SDK。

版本变更、下载与校验文件统一发布在 [GitHub Releases](https://github.com/n1ght-ow/myscore/releases)。本 README 只描述当前功能、使用方式与数据边界，不记录更新日志。

## 赛事覆盖

- 足球：英超、欧冠、Carabao Cup、FA Cup。
- NBA、NFL：当前比分、节次与来源计时。
- F1：按练习、排位、冲刺、正赛拆分场次；详情分「总览、车手、成绩」三栏，车手按车队分组，含车号，成绩含圈数、用时、积分与 Q1–Q3。
- CS2：仅 Spirit 主队，使用 5EPlay 战队 ID `csgo_tm_7020`，不匹配 Spirit Academy。
- LOL：仅 Worlds / World Championship，排除其他联赛及 Esports World Cup。
- 电竞展示系列赛比分及来源提供的小局信息；没有提供的地图赢家或回合比分不会推断。

## 直播入口

- 英超、NBA：列表、比赛详情和平板阅读页的播放键统一查找并打开咪咕视频的**本场单场页面**；只在咪咕公开搜索同时匹配到双方中文队名和开赛时间（±20 分钟）时打开。首次点击会等待查找完成，复用正在进行的请求和已有单场缓存，不为每张可见卡片发一次搜索。查找失败或尚未发布时明确提示，可自行选择打开联赛专区，不会自动跳到总页。
- CS2：斗鱼 6657 直播间。
- LOL Worlds：进行中或未开始使用虎牙 149361 直播间；已结束自动切换为哔哩哔哩官方账号「2026全球总决赛」系列中按日期、双方队代码匹配的**全场录像**。录像尚未发布时显示「录像待发布」，不会误跳直播间。
- 手机与平板的比赛卡在右下角并排放置订阅与播放图标，比分与末端操作共用中心轴、堆叠队徽与时间/来源共用左边缘，统一浅灰色、无图标底色、48dp 点击区域；长按播放键可查看平台与目的地类型，录像待发布时显示时钟。详情比分牌底部只保留平台和简短的目的地状态；点击交给系统浏览器或已安装的应用，不在应用内嵌播放器，也不绕过会员、登录或地区限制。
- F1、NFL、欧冠、Carabao Cup 与 FA Cup 暂不显示直播入口。
- 动态查找在后台执行并缓存：哔哩哔哩系列约 15 分钟、咪咕单场约 12 小时、后台失败退避 5–10 分钟；手动点击咪咕播放可重新尝试，网络失败会提示，不影响比分和详情刷新。哔哩哔哩与咪咕均为公开网页接口而非签约 API，可能变更或限流，界面保留明确标注的备用入口。

## 刷新与缓存

- 只有进行中或临近开赛的比赛才自动检查：列表进行中约 10 秒，临近开赛约 30 秒，远期赛程约 30 分钟检查一次（2 小时内直接复用上次读取）。
- 切到某一天先显示内存或本地的上次结果，再在后台刷新；150 毫秒内的连续切换只为最后一天发起请求。停留时后台预取后一天的赛程与列表队徽，点下一天通常直接出内容；预取失败不会写成该日的来源错误，打开时仍会重试。
- 远期日期成功读取后 2 小时内复用，临近开赛仍按 25 秒检查；过去日期 6 小时。重复查看同一日期不再重新等来源返回。
- 来源确认已结束或已取消的比赛只读取一次，自动刷新不再修改其比分、状态和更新时间；全部结束或过去日期不再自动轮询，点右上角可手动重新核对。
- 失败来源单独延长重试间隔，离开前台停止轮询；慢来源不会阻塞其他来源。连接失败时保留真实缓存与更新时间。
- 列表等手指松开、滚动稳定后更新，滚动中不重建；快速切换日期或赛事时优先当前选择；返回前台先显示已有缓存。
- 平板阅读页只在比分、状态或详情内容变化时重绘；系统内存紧张时主动释放队标记忆缓存，返回后按需从本地缓存重载。
- 任意日期按 Asia/Shanghai 划分。凌晨的美洲比赛会合并前一个来源日期后再次按北京时间筛选。
- 请求失败时显示错误和真实缓存的时间；不会加载模拟比赛。

## 平板布局（Xiaomi Pad 6S Pro 12.4）

Pad 6S Pro 12.4 是 12.4 英寸 3K LCD，3048 × 2032、3:2、294 ppi、144Hz；按 320 dpi 计算为横屏 1524 × 1016 dp、竖屏 1016 × 1524 dp。应用没有把手机列表拉宽，而是在 `smallestScreenWidthDp >= 720` 时进入独立工作台：

1. 左侧 128dp 导航轨分两层：上方「比赛 / 设置」是页面导航，当前页面用文字明度强调；下方「赛事筛选」是二级筛选，选中项用冷绿竖条和正文色加粗，不再和页面导航共用同一种选中态。设置页这组标题变为「跳到赛事」，不显示筛选选中态，点任意赛事即切回比赛页。当天全部来源已知时显示场次数，只筛选单一赛事时其余场次显示「—」并保留进行中绿点。切换赛事、页面或日期会重建整条导航轨，绿条与实际列表同步；旋转后保留已选比赛。
2. 中间赛程轨显示日期、赛事分组、比赛时间、队标、比分、状态和单场日历按钮；点一张卡在右侧阅读页查看比分、数据、进程与来源，再点一次或点「打开比赛中心」进入完整体育详情。选中卡只用表面明度和一个小勾选标记，不使用通栏绿线；勾选表示当前阅读对象，日历图标才表示订阅。
3. 右侧阅读页使用 96dp 队徽与 64sp 比分头版，下面按实际内容宽度排列技术统计、最新进程、比赛信息与来源；空的一侧不占栏，来源使用无底色文字。

布局按当前窗口和系统显示缩放计算，不固定假定 320dpi。导航轨可滚动，字号较大时适当加宽；扣除导航轨后可用宽度不足 850dp，保留完整高度的赛程，点击比赛进入单列详情。切换赛事原地同步导航选中状态、绿色标记和无障碍说明；切换比赛从阅读区顶部开始，后台更新等待手指松开和惯性滚动结束。较新的单场详情同步到左侧同一比赛，旧结果不会把比分或状态改回去。

宽度至少 1000dp 的详情页使用左侧 404dp 比分 / 比赛信息 / 来源资料栏和右侧标签阅读区；球队页并排显示「接下来」与「已结束」。较窄窗口使用单列详情和球队赛程。设置页在宽屏使用双栏布局，在窄窗口或大字号下上下排列；日历、订阅与来源各保留一处入口；弹层在平板上居中显示。足球阵容、NBA / CS2 两队选手和进程只在足够宽时并排，首页比分牌在窄窗口使用上下两队行式；手机尺寸继续使用原有单列布局。

## 安装与使用

1. 从 [GitHub Releases](https://github.com/n1ght-ow/myscore/releases) 下载最新 APK；已安装用户也可在「设置 → 检查更新」获取最新版。包名与签名保持一致，可直接覆盖安装并保留设置、缓存与日历关联。
2. 「比赛」页切换足球、NBA、NFL、F1、CS2 或 LOL。点日期打开月份日历，或用左右箭头前后一天。
3. 点比赛打开完整详情；点队标进入该队赛程，可筛选全部、接下来与已结束。
4. 在比赛卡右下角点日历加号订阅单场，提前 5 分钟提醒。首次授权后优先写入小米账户日历，没有则本机日历。勾选表示已订阅，再点可确认取消。
5. 「设置」管理已订阅比赛、目标日历、外观、数据来源和更新。系统日历负责提醒，请在手机上允许日历通知。

最低 Android 9。APK 为保持既有签名的个人安装 debug 包；不要先卸载，否则会清除应用设置、缓存和日历关联。构建输出为 `app/build/outputs/apk/debug/app-debug.apk`。

## 应用内更新

更新读取本仓库 GitHub Releases 正式版，安装前检查 SHA-256、包名、版本和签名，由系统安装器确认覆盖安装。下载由应用的前台服务执行，离开页面后继续；优先使用官方附件 API，连接失败时切换发布附件地址。下载不请求共享存储权限；连接超时会有限重试并给出可重试的错误，旧系统下载任务不会阻塞新下载。

## 队标与比赛详情

浅色模式以白色为主，深色模式以石墨深灰为主，可跟随系统或在设置切换。首页保留紧凑的队标／队名／比分列表，点击比赛进入完整详情页，系统返回键回到列表。顶部标题、赛事筛选和日期排成紧凑的一层：上滑时随列表收起，下滑时立即展开；切换页面或日期会重新展开。

- 足球四项赛事：球场、阵型、首发与替补、换人状态、双方技术统计、进球/红黄牌/换人等关键事件。
- NBA：四节比分、球队对比与逐回合进程；球员页按主队、客队上下两栏显示真实头像、球队标识、球衣号、位置与来源出场状态，伤停名单放在所属球队横栏底部。数值列排序、横向滚动同步和姓名详情继续保留；投篮、三分、罚球、正负值等列可横向查看。
- NFL：分节比分、球队对比与得分进程；球员按传球 / 冲球 / 接球 / 防守等分类，支持队伍筛选和紧凑表格比较。
- F1：总览、车手、成绩三栏；车手按车队分组，含车号，成绩含完成圈数、成绩/用时、积分及来源提供的 Q1/Q2/Q3，另有比赛周末赛程。当前不提供逐圈事件流或车载遥测。
- CS2 Spirit 主队：总览 / 选手 / 小局三栏。总览只保留赛事、赛制、阶段与来源；选手页只显示全场两队总数据；小局页用地图按钮切换一张图，选中图的两队横栏内各有「T 方 / CT 方 / 加时 / 总分」比分条和本图选手表，比分条以该队首开方为第一列，T/CT 由来源侧别角色映射，地图总分与选手数据随按钮一起切换。
- LOL Worlds：总览 / 比赛 / 统计三栏。按小局切换，双方按位置对照，显示真实英雄头像、等级、K/D/A、补刀、经济和召唤师技能；目标区对照推塔、大小龙、先锋、巢虫等，统计页展示伤害、视野与装备图标，宽屏将双方十位选手同表排列，窄屏使用单队紧凑分组。支持来源返回的进行中快照与已结束小局，不用历史队员推算本场未发布阵容。官网未提供实时小局时明确显示未提供；暂时失联时保留上次数据并标记原获取时间。

上述信息以每场来源实际提供为准：未开赛阵容可能尚未发布，较低覆盖的比赛可能缺少统计。ESPN 未开赛摘要中附带的赛季累计数据不作为本场统计展示，旧缓存也执行相同检查；足球已发布首发、替补和伤停信息仍保留。没有提供的字段显示暂无或 `—`，不补零，不用示例数据。普通宽表固定姓名列，球员表默认先显示 16 人并可继续展开；LOL 对位表保持姓名与各列的最小可读宽度，窄屏和大字号时横向滑动查看整表。比赛信息按字段分组，裁判只显示可读职位与姓名；进程分批加载。ESPN 的部分事件描述和专有字段保留来源英文，不生成 SofaScore 专有评分。

队标使用 ESPN、5EPlay、英雄联盟官网提供的真实图片；下载失败时退回队名缩写，刷新可重试。图片和详情均有本地缓存；按列表／详情绘制尺寸裁切后的队标小图也会单独缓存，重开应用直接解码，图片请求复用同一 CDN 的连接。F1 是车手排名赛事，不在比赛首页虚构两队队标。

## 球队赛程

队标是球队赛程入口：在比赛列表中点击某队队标（48dp 触摸区），或进入详情后点击比分条上的队标，会打开该队的赛程页。若来源尚未提供球队标识，队标不做跳转，点击仍由比赛卡打开详情，避免按队名猜测球队。

球队页顶部显示真实队标、队名和赛事，下面一行是来源、场次与获取时间。列表默认显示「接下来」，两栏都有比赛时可用「全部 / 接下来 / 已结束」快速切换。每张卡显示北京时间日期与开赛时间、对手、场地或赛事阶段，以及按本队视角排列的比分和胜 / 平 / 负；比分统一为本队在前，点开比赛后详情比分条按来源的主客方向显示。CS2 / LOL 是系列赛，不显示主客场字样。

- 足球、NBA、NFL：ESPN 球队本赛季 schedule。足球同时请求已结束结果和 `fixture=true` 的剩余赛程后合并；NBA / NFL 一次返回整季。
- CS2：5EPlay `team/matches_v1` 战队赛程，显示该队最近 30 场已结束比赛和接下来已发布的比赛；主页面的 CS2 列表仍只显示 Spirit 主队。
- LOL：只读取官网 Worlds 赛程，按来源战队 ID 筛出该队场次；不包含其他联赛。
- F1 没有球队赛程，车手和车队不提供队标入口。

球队页默认进入「接下来」，每场已确认时间且尚未开始的比赛可直接点右下角日历加号图标，写入系统日历并提前 5 分钟提醒。成功后图标变为日历勾选，再次点按确认后取消；未确认时间、延期或已开始的比赛不提供新订阅操作。订阅状态与首页及设置共用。

球队页静态赛程缓存 30 分钟，进行中、临近开赛和延期比赛使用更短缓存，返回前台按比赛状态检查是否过期。进行中或临近开赛时前台每 30 秒更新，远期赛程低频检查，全部结束或空赛程停止轮询；失败后约 1 分钟重试，保留上次成功获取的比赛、失败原因和原获取时间，也可由右上角手动刷新。空赛程与连接失败分开显示，缺失比分保持未知，不补 0。

## 日历规则

日历只按单场比赛订阅：在比赛卡上点日历加号图标后写入系统日历，提前 5 分钟提醒；图标变为日历勾选后可再次点按取消，或从设置列表取消。首次订阅只请求日历权限，自动优先选择小米账户日历（没有则本机日历），不弹出日历选择；设置页仍可手动更换。日历选择器优先显示小米账户/本机日历，过滤不可写与不可见日历，并把 `calendar_displayname_xiaomi` 这类系统资源键显示成可读名称。日历 Provider 的枚举、订阅与取消都在后台线程执行，系统日历响应慢时不阻塞界面。

只维护带有 MyScore 包名、比赛唯一标记和本机事件关联的日程；不修改其他个人事件。同一比赛重复订阅不新增，改期更新原事件，来源明确取消时删除原事件，延期/时间待定时撤销旧提醒。日历中结束时间为估算，说明中会标注。

后台由 Android JobScheduler 约每小时检查已订阅比赛并在重启后保留，可能被省电策略或断网延后；打开应用会补检查，进入或恢复设置页也会检查。来源确认已结束后移除本机订阅记录与提醒，系统日历保留历史日程。不会按估算时长推断结束。检查只更新已订阅的比赛，不会自动导入未订阅的赛事。小米 / 澎湃 OS 可能限制后台任务，需在系统中允许日历通知与后台运行。

## 数据源及网络边界

当前体育接入 ESPN 公开网站比分、summary、球队 schedule 和 F1 场次统计接口，CS2 接入 5EPlay 公开赛程、战队赛程和比赛详情，LOL 接入腾讯英雄联盟赛事官网赛程及官网使用的腾竞小局详情。它们不是本项目签约的数据服务，可能有延迟、字段变化或访问限制。无需用户账号或 API Key；LOL 网页的公开客户端配置从官网在运行时读取，仅保存在内存，不把凭据硬编码到 APK，不展示接口中附带的赔率。LOL 同时显示源数据自带的发布时间，详情另显示获取时间，避免把下载时间当成比分更新时间。

HLTV / SofaScore / BO3.gg 在未配置代理的开发环境请求中出现过 403，不作为默认来源。5EPlay 当前全局列表最多检查前 100 场，结合 Spirit 主队的未来/历史接口获取赛程；球队页对任意 5EPlay 战队 ID 读取同一战队赛程接口，来源限流时显示稍后重试，不把限流当成没有比赛。遇到分页限制时保留未知范围。开发环境访问成功不能代表所有中国内地移动运营商、地区、时段均稳定可用；K80 Pro 真机和移动网络验收仍需进行。

直播目的地另读取哔哩哔哩公开的视频系列元数据和咪咕公开搜索的赛事卡片元数据，只用于生成外链，不作为比分、阵容或详情来源。两者都不需要登录、Cookie 或 API Key，App 不保存账号信息；接口失败、限流或条目缺失时保留专区 / 待发布回退。播放、会员和地区限制仍由对应平台决定。

## 开发与验证

使用 JDK 17 和 Android SDK 35，配置 `ANDROID_HOME` 或 `ANDROID_SDK_ROOT`。没有第三方生产依赖；JUnit 和 org.json 仅用于本地测试。


## 阵容与数据来源

足球阵容只用球衣号、姓名和事件标记呈现：进球、黄红牌、换下 / 换上；球员详情弹层保留来源字段，替补行显示被换下或换上的球员姓名。比赛数据来自 ESPN；统计页的球员图片优先使用 ESPN 提供的照片，缺失时按完整姓名和出生日期匹配英超官方图片，再尝试 TheSportsDB 备用头像，身份不可靠时保留姓名缩写。

应用没有接入单场评分、跑动和身价数据源，缺失字段显示「—」，不以 FPL 积分、BPS 或赛季状态生成评分。评分仍需另行接入覆盖所需赛季的数据源；已核查 [API-Football 单场球员统计](https://www.api-football.com/documentation_v3) 与 [Sportmonks 球员统计](https://www.sportmonks.com/football-api/football-stats-api/)，均需要服务 Key。

NBA 球员页按主队、客队上下两栏显示，姓名列不重复球队文字，保留头像旁队徽。首发使用绿色标签，替补使用中性标签，未出场单独标记；号码与位置仍保留，窄屏及大字号下自动换行。伤停名单放在所属球队横栏底部，状态使用来源值的中文映射；不提供双方 / 单队筛选或独立的伤停筛选页。排序、数据横滑同步及姓名详情继续可用，完整球队身份仍保留在详情和无障碍描述中。

CS2 详情把「总览 / 选手总数据 / 小局比分 / 每张地图的数据」分开呈现：总览只放赛事、赛制、阶段和来源；选手页只放全场两队总数据；小局页用地图按钮切换，一次只显示一张图。选中图的两队横栏内各有「T 方 / CT 方 / 加时 / 总分」比分条和本图选手表；比分条以该队首开方为第一列，T/CT 由来源 `fh_role` / `sh_role` 映射。地图总分只出现一次，没有全部分图拼在一起的比分表或独立攻守半场表；Nuke 这类没有逐图数据的地图不生成按钮或空表，只在末尾提示。来源没有提供的字段保持未知，不以 0 或推算值补齐。

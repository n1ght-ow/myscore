# 数据扩展与导航审查

审查以 `4.13.1` 为基线，目标是让更多已发布的数据能从正确的对象找到，不把所有内容堆进当天赛程。这是应用数据与导航的源码审查，不是全量真机视觉验收，也不是对外部接口可用性的保证。

## 页面各自回答什么

- **Scores：这一天有哪些比赛？** 保留日期、运动、比分与单场操作。切换日期不改变赛季榜单，也不在列表上为每场额外加载详情。
- **Standings / Tournaments：这个赛事整体怎么样？** 积分榜、分区、杯赛轮次、Valve 排名和 5EPlay 赛制各属于自己的范围。单场可直达它所属赛事；历史比赛通往的是明确标注的当前榜单或轮次，不是假设同赛季。
- **Match：这场发生了什么？** 总览是摘要、比赛信息与相邻入口；阵容、球员数据、进程、地图或成绩仍放在各自标签，不以复制全表增加“详细度”。从 CS2 签表打开单场时，用系统返回回到原签表，不再打开它的第二个实例。
- **Team：这支队最近和接下来打什么？** 球队赛程复用真实来源 ID。从比赛队标或同源榜单都可到达；Valve 与 5EPlay 没有已核实映射时，排名战队不凭名称跳转。
- **Settings / Update：如何管理应用？** 日历、通知、播放平台、来源诊断与 APK 校验不是体育数据层。本轮保留原权限、后台任务和发布流程。

## 审查发现与首批落地

- 榜单解析有 ESPN 球队 ID，却未传到榜单行；这使读者知道排名但不能继续查赛程。保留并缓存 ID，让英超、欧冠、NBA、NFL 的可识别球队行可点；旧快照仍可读，没有 ID 时等成功刷新。
- 榜单数据比表格更丰富。验证 ESPN 当前返回后，足球增加进球/失球，NBA 增加主客场战绩、近十场、连胜负，NFL 增加得分/失分。补充列沿用表内横滑和冻结身份列，不挤掉首要指标。
- ESPN 的场馆、场地类型、中立场地和裁判角色部分没有进入详情或未正确解析。消费已发布字段，忽略未知值；F1 可复用赛历里的赛道地点。平板比赛信息不再静默截到固定条数，且只在一个位置显示同一条警告。
- 赛事入口以前主要从首页进入：单场只能打开 CS2 赛事，其他运动回首页还要重找榜单。补上精确到赛事的直达，国家队无对应榜单时不出现空入口；CS2 当前排名也能浏览赛事签表。
- 数据源与缓存已有独立分层：`Repository` 按日期聚合比分，`DetailRepository` 按单场缓存，`TeamRepository` 按球队缓存，`StandingsStore` 按赛事缓存。新增字段先用现有请求；过去赛程、详情缓存和榜单快照不等于长期历史档案。网络失败与没有发布数据不能合并为同一结论。

## 下一批任务与验收门槛

1. **杯赛轮次 → 单场。** 在 `CupStandings` 保留 ESPN event/competition ID，让已识别对阵像 CS2 签表一样可钻取，回退保留轮次和滚动位置。先以真实足总杯及联赛杯样本核对，未确认对阵和旧无 ID 快照保持只读。
2. **赛事和球队历史。** 先调查 ESPN 和 Jolpica 支持的赛季参数、季前/常规/季后范围及响应身份，再加赛季选择。各赛季单独缓存；请求失败不得回退展示其他赛季的数据。CS2 的榜单日期和赛事日期分别保留，绝不把 Valve 排名当作赛事晋级结果。
3. **比赛进程和选手档案。** 优先验证 NFL ESPN drive/play 数据能否按攻防回合展开，沿用现有比分事件作为摘要；足球、NBA、CS2 只扩充能按来源 ID 验证的球员字段。真实进程按需加载，缺少动作、地图或选手数据不补造。

每批先记录来源、对象 ID、赛季/日期范围以及字段缺失表现；再加真实 fixture、缺失和旧缓存回归；最后用手机和平板核对入口、返回、对齐、横滑和大字号。把运行证据及未覆盖状态写入 `VERIFICATION.md`。
